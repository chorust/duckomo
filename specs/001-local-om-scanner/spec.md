# Feature Specification: Phase 0–2 本地 OM 可用扫描器

**Feature Branch**: `main`（当前分支；本次未配置分支创建 hook）

**Created**: 2026-09-28

**Status**: Draft

**Input**: User description: "Phase 0–2"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 直接查询本地单变量文件 (Priority: P1)

作为气象数据分析者，我希望直接查询一个已知维度和形状的本地 OM 文件，获得可与官方读取结果核对的值，不必先转换数据格式。

**Why this priority**: 对单变量结果的可信验证是后续扫描器的基础，对应 Phase 0。

**Independent Test**: 使用一个有来源、已知形状和参考值的本地单变量样本，通过初期验证入口扫描全部数据，核对行数、逻辑顺序、数值和缺测位置。

**Acceptance Scenarios**:

1. **Given** 一个支持的单变量样本及官方读取参考结果，**When** 用户执行完整扫描，**Then** 每个逻辑位置恰好出现一次，数值和顺序符合参考结果及声明的数值容差。
2. **Given** 样本包含缺测值，**When** 用户查询，**Then** 缺测位置按已公布的缺测值规则呈现，且不与有效零值混淆。
3. **Given** 已构建并加载的扫描器和本地样本，**When** 用户在未安装 Python 的运行环境中查询，**Then** 查询成功，不要求预先转换文件。
4. **Given** 路径不存在、文件不可读或文件损坏，**When** 用户扫描，**Then** 查询明确失败并说明失败类别，不把部分数据作为成功结果返回。

---

### User Story 2 - 理解文件结构并查询全部变量 (Priority: P2)

作为分析者，我希望查看文件有哪些可查询列及其类型，并在一次查询中读取相互对齐的变量；当文件不提供经纬度或时间含义时，我仍能查看受支持的原始值，而不会得到猜测的坐标。

**Why this priority**: 让初期验证能力成为可发现、可解释的日常查询入口，对应 Phase 1。

**Independent Test**: 分别对纯数组样本和带层级、多变量样本查看列描述并扫描全部列，核对列名、类型、行数、变量对齐和重复查询的一致性。

**Acceptance Scenarios**:

1. **Given** 一个受支持的纯数组文件，**When** 用户查看列描述并扫描全部列，**Then** 获得稳定的列名、类型和逻辑行解释，结果不依赖文件名中的暗示。
2. **Given** 层级文件包含共享逻辑维度的多个受支持变量，**When** 用户扫描全部列，**Then** 所有变量以已记录的命名规则出现，同一行对应同一个逻辑位置。
3. **Given** 文件缺少可靠的网格或时间语义，**When** 用户查看列或查询值，**Then** 原始值仍可读取，但不会出现凭空生成的经纬度或时间列；请求不可用语义列时明确失败。
4. **Given** 文件存在不支持的类型、布局或无法对齐的变量，**When** 用户查看列描述或扫描，**Then** 查询在返回数据前明确拒绝该文件并解释限制，不静默丢弃变量或进行隐式广播。
5. **Given** 不同层级的变量具有相同叶名称，**When** 用户查看列描述，**Then** 变量可通过稳定且唯一的列名区分；不能唯一表示时明确拒绝。

### User Story 3 - 仅为查询所需变量付出读取成本 (Priority: P3)

作为只需要少量气象变量的分析者，我希望选择列后减少实际读取和解码工作，并能够验证这种减少，同时保持过滤、表达式和聚合结果正确。

**Why this priority**: 避免无关变量成本是本里程碑的性能价值，对应 Phase 2。

**Independent Test**: 在包含至少两个可独立读取的变量的同一固定样本上，对比全变量查询、单变量查询及引用额外过滤变量的查询；核对结果和实际读取、解码记录。

**Acceptance Scenarios**:

1. **Given** 多变量样本，**When** 用户仅选择一个变量，**Then** 结果与完整扫描后选取该变量相同，无关变量的数据不被解码，且数据读取字节少于全变量扫描。
2. **Given** 查询输出变量 A 并用变量 B 过滤，**When** 查询执行，**Then** B 仍被正确读取以完成过滤，结果与完整扫描基准一致，其他无关变量不被解码。
3. **Given** 查询重排、重复引用变量或对变量计算表达式，**When** 查询执行，**Then** 输出顺序、名称和数值遵循查询语义，变量裁剪不改变结果。
4. **Given** 只请求行数的查询，**When** 查询执行，**Then** 行数与完整扫描一致；若验证过的元数据足以确定行数，不解码任何值变量。
5. **Given** 常量假条件或过滤后无匹配行，**When** 查询执行，**Then** 返回零行且不产生伪造记录；普通过滤不承诺减少行范围读取。

### Edge Cases

- 支持的空数组返回零行且仍提供稳定列描述；不支持的零长度维度必须在支持矩阵中明确列出并拒绝。
- 扫描跨越多个输出批次时，不得丢失、重复或错位逻辑位置。
- 非方形多维样本用于暴露轴交换或展平顺序错误；不得假定所有文件都是时间乘网格。
- 缺测标记、非有限值及类型边界按已声明规则处理，不能静默溢出或与有效数值混淆。
- 形状相同但维度含义不同的变量不能仅凭形状自动对齐。
- 损坏的元数据、截断的数据及不支持的文件版本必须报告错误，不能被解释为空文件。
- 列描述可以读取必要元数据；不应为发现模式而解码全部变量值。
- 查询取消、失败或重复执行后，文件资源可释放；连续查询不得耗尽可用文件句柄。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持直接查询本地受支持 OM 文件，无需先转换格式，查询运行时不依赖 Python。
- **FR-002**: Phase 0 MUST 提供单变量验证入口，使用具有已知形状的样本证明数据值、维度展平顺序与官方读取结果一致。
- **FR-003**: 系统 MUST 在返回数据前确定稳定的列模式，依据文件元数据识别层级、变量名称、类型、维度及形状；查看模式不得解码全部变量值。
- **FR-004**: Phase 1 MUST 提供常规扫描入口和列描述能力，至少覆盖一个纯数组样本及一个带层级的多变量样本，并公布各自的列名和行语义。
- **FR-005**: 系统 MUST 将每行解释为一组逻辑维度索引处的值，仅对有证据共享逻辑维度的变量按位置对齐；未支持的对齐方式必须拒绝，不做隐式广播或笛卡尔积。
- **FR-006**: 系统 MUST 使用稳定且唯一的变量列名，公开层级重名和无变量名纯数组的命名规则，不从文件名猜测变量或轴语义。
- **FR-007**: 系统 MUST 仅在映射已可靠验证时暴露语义坐标列；缺失语义不妨碍受支持原始值扫描，请求不可用语义列必须失败并指出信息不足。
- **FR-008**: 系统 MUST 公布并测试受支持的文件版本、布局、变量类型、数值容差、缺测值映射和非有限值规则；未支持的类型或布局必须在返回数据前拒绝。
- **FR-009**: Phase 2 MUST 只解码查询实际依赖的值变量；输出、过滤、表达式、排序或聚合所需变量都属于依赖，不得提前裁剪。
- **FR-010**: 系统 MUST 保持投影列顺序、重复引用、表达式、过滤和聚合的查询语义；不能安全优化的条件必须按完整读取结果正常计算。
- **FR-011**: 系统 MUST 正确处理只计数和空结果查询；元数据足以确定行数时，计数不得解码值变量。行范围的过滤优化不属于本阶段承诺。
- **FR-012**: 每个阶段 MUST 提供可复现样本、来源或生成方法、执行命令和结果记录；与官方参考结果对照行数、逐位置值、缺测和顺序，跨输出批次及非方形多维样本也必须覆盖。
- **FR-013**: Phase 2 MUST 提供全变量与单变量查询的实际读取字节数、读取请求数、解码块数、耗时及峰值内存记录；能区分变量数据与共享元数据开销，并证明无关变量解码为零。在可独立读取的固定多变量样本上，单变量数据读取字节必须严格少于全变量读取。
- **FR-014**: 系统 MUST 对不可读、损坏、截断和不支持的文件明确报错；查询失败或取消后必须释放文件资源，并可成功执行下一次有效查询。
- **FR-015**: Phase 0 MUST 记录验证采用的依赖与格式版本、样本布局及读取边界；Phase 1 MUST 固定可对外承诺的支持子集和语义。改变仓库既有用户语义或职责边界的发现必须同步更新基线文档。

### Key Entities *(include if feature involves data)*

- **OM 文件**：本地路径标识的数据来源，具有格式版本、布局、元数据及零个或多个数组变量；只有明确支持的子集可被扫描。
- **变量**：具有唯一查询名称、数值类型、维度与形状的数据数组，可能位于层级路径下。
- **逻辑位置**：有序维度索引组合，确定一行及各兼容变量在该行的值，不自动代表经纬度或时间。
- **列模式**：一次查询可发现的稳定列名和类型，以及有证据支持的行、维度和变量对应关系。
- **验证样本与参考结果**：固定数据、来源、预期值与容差、缺测规则及扫描顺序的证据。
- **扫描观测记录**：与固定样本和查询关联的读取、解码、耗时和内存证据，用于证明列裁剪有效。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在公布的支持样本集上，完整扫描和裁剪扫描的行数、逐位置数值、缺测位置均有 100% 的检查通过率；数值比较使用事先记录的容差。
- **SC-002**: 至少一个纯数组样本、一个层级多变量样本、一个非方形多维样本及一个跨批次样本完成可复现验证；样本可以同时承担多个覆盖角色。
- **SC-003**: 固定多变量样本上，单变量扫描对无关变量的解码数为零，变量数据读取字节严格小于全变量扫描；完整记录共享开销及其余观测指标，不以耗时波动代替读取证据。
- **SC-004**: 过滤依赖、表达式、重排、重复变量引用、只计数及空结果六类查询与完整扫描基准的结果一致率为 100%。
- **SC-005**: 不可读文件、损坏文件、不支持的布局或类型、维度不兼容及语义缺失五类负向用例均产生预期行为，无静默错误坐标或成功返回的残缺结果；取消或失败后可再次成功查询。
- **SC-006**: 一名未参与实现的验证者可仅依照交付说明，在不安装 Python、不预转换数据的查询环境中完成加载、查看列描述、完整扫描及单变量扫描四项操作，并复现参考结果。

## Assumptions

- 范围依据 [Roadmap](../../docs/roadmap.md) 的 Phase 0–2，产品语义依据 [v1 Spec](../../docs/spec.md)；[架构文档](../../docs/architecture.md) 的实现约束由后续 plan 承接，本规格不重新选择技术方案。
- 已有目标入口名称沿用 Phase 0 的 `read_om_raw(path)` 和 Phase 1–2 的 `read_om(path)`；前者用于验证，不新增长期兼容性承诺。全部列查询及列描述分别沿用 `SELECT *` 和 `DESCRIBE` 的产品用法。
- 具体依赖版本、首批支持类型、列名映射及数值容差依赖 Phase 0 的真实样本证据，在 Phase 1 承诺支持前记录并验证；不预设任意 OM 布局都能读取。
- 默认本阶段面向单个本地文件、扫描期间内容不变；多文件合并、文件动态变更一致性不在范围内。
- 缺少坐标或时间语义时默认只提供可验证的原始值及其逻辑解释；domain 注册、坐标生成和时空映射不成为本里程碑的先决条件。
- 空间下推、时间及其他维度下推、HTTP/S3、并行和缓存优化、完整网格覆盖、科学计算与导出均不在本次范围；后续按 Phase 3–7 推进。
- 官方可读取的可复现本地样本和参考结果是验证依赖，至少需要一个变量数据可独立读取的多变量样本。参考数据准备可使用官方工具，扫描运行时仍不依赖 Python。
- 读取比较采用相同固定文件、相同环境及一致缓存条件，区分元数据和变量数据开销；不凭空规定耗时或内存阈值。
- 当前 constitution 仍为未填写模板，不将示例原则当作已批准治理规则。
