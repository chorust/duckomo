# Feature Specification: Phase 4–5 维度语义、远程与并行读取

**Feature Branch**: `main`（当前分支；未配置分支创建 hook）

**Created**: 2026-09-30

**Status**: Draft

**Input**: User description: "完成Phase 4～5"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 按时间、层次和预报身份理解数据 (Priority: P1)

作为气象数据分析者，我希望为数据的 time、level、lead_time、member、run 指定可信的含义，并将这些坐标与数值一起查询，以便区分有效时间、垂直层次、预报时效、集合成员和起报时间。

**Why this priority**: 正确的维度身份是组合查询、远程局部读取和并行结果核对的基础。

**Independent Test**: 使用坐标和值均有独立参考的本地多维样本，逐位置检查五类语义列；在轴顺序不同的等价样本上按完整坐标比较结果。

**Acceptance Scenarios**:

1. **Given** 文件具有已识别且完整的坐标证据，或用户提供完整显式映射，**When** 查看列描述并查询，**Then** 每行新增的语义坐标与该行数值正确对应，坐标长度与对应轴长度一致。
2. **Given** 明确声明的 time、run、lead_time、level 和 member，**When** 查询坐标，**Then** time 表示有效时刻、run 表示起报时刻、lead_time 表示相对起报时刻的时长、level 保留声明的垂直类型和单位、member 保留源成员标识；不把索引当成物理坐标。
3. **Given** 非标准轴顺序、单元素轴或不等间距坐标，**When** 读取多变量，**Then** 各变量按同一逻辑位置对齐；不同样本的轴排列不影响坐标含义，也不隐式转置不兼容变量。
4. **Given** 未启用任何维度语义映射，**When** 执行既有查询，**Then** 保持原有列及值行为；缺少可靠含义的轴继续保留原始逻辑位置。
5. **Given** 映射长度错误、同一轴被重复赋予语义、未知单位、冲突证据或列名冲突，**When** 请求语义坐标，**Then** 在返回数据前明确拒绝并定位问题，不猜测、不覆盖。

---

### User Story 2 - 联合筛选空间和其他维度 (Priority: P1)

作为只关心特定时段、层次或成员的分析者，我希望将这些条件与空间和数值条件组合，既得到精确结果，也避免读取不相关数据。

**Why this priority**: 这是 Phase 4 的实际使用价值，也决定 Phase 5 能否节省网络传输。

**Independent Test**: 对跨多个块的固定样本，先完整读取形成独立基准，再比较单维及混合筛选的结果、读取量和解码量。

**Acceptance Scenarios**:

1. **Given** 五类已映射维度，**When** 对 time、run、lead_time、数值 level 使用常量等值或范围条件，对 member 使用等值条件，或以合取组合这些条件，**Then** 结果与完整扫描后过滤一致，并缩小到覆盖全部匹配记录的候选位置。
2. **Given** 空间、时间、成员和数值过滤并存，输出变量与过滤变量不同，**When** 查询、聚合或重排输出列，**Then** 所有过滤仍精确生效，变量不发生错位，不读取无关值变量。
3. **Given** 相互矛盾的条件或完全越界的坐标范围，**When** 能仅凭坐标确定为空，**Then** 返回零行，值索引、值数据读取与值块解码均为零。
4. **Given** 只查询语义坐标或按坐标计数，**When** 不依赖值变量，**Then** 返回正确坐标或计数，不读取值变量的索引和数据，也不解码值块；允许必要的坐标及元数据读取。
5. **Given** 非单调坐标、重复坐标、混合 AND/OR、函数或转换条件，**When** 无法安全缩小范围，**Then** 保留全部可能匹配位置并精确过滤；重复坐标对应的不同逻辑位置全部保留。
6. **Given** 可跳过块的固定样本及受支持的窄范围条件，**When** 比较同列全扫与局部查询，**Then** 局部查询的值数据字节与解码块数均严格减少。

### User Story 3 - 直接查询远程 OM 文件 (Priority: P1)

作为使用远程气象资料的分析者，我希望直接查询 HTTP(S) 或 S3 上的单个 OM 对象，沿用本地文件的维度、空间和缺测语义，并只传输所需部分。

**Why this priority**: 免去手工下载与转换，是 Phase 5 的核心入口。

**Independent Test**: 将内容相同的固定样本放在本地、支持局部读取的 HTTP 服务和 S3 存储，分别运行全扫、局部、空选择与混合查询，核对结果及实际网络读取记录。

**Acceptance Scenarios**:

1. **Given** 本地和两个远程来源中的同一内容，**When** 执行相同查询，**Then** 列描述、坐标、值和缺测位置一致，无额外重复或遗漏。
2. **Given** 需要访问授权的 S3 对象和用户已配置的有效访问凭据，**When** 查询，**Then** 正常读取；无权限或凭据失效时明确失败，诊断和观测记录不暴露访问密钥或签名信息。
3. **Given** 支持局部读取且有可跳过块的远程对象，**When** 冷缓存下查询窄范围，**Then** 服务端记录的响应数据总字节严格少于同列全扫，不以预先完整下载充当局部读取。
4. **Given** 远程服务不支持所需局部读取、对象不存在、短读或超时，**When** 查询，**Then** 返回可识别原因的失败；不把残缺响应当作完整数据，也不静默退化为完整下载。
5. **Given** 扫描期间可检测到对象版本或长度改变，**When** 继续读取，**Then** 查询失败，不成功返回由不同版本拼接的结果。

### User Story 4 - 并行完成大范围扫描 (Priority: P2)

作为分析者，我希望扫描较大文件时能使用多个工作者，并能限制并行度，在本地和远程查询中维持相同的正确性。

**Why this priority**: 在正确读取基础上提高大范围分析效率，可独立于缓存验收。

**Independent Test**: 在同一固定多块样本上使用单个及至少两个工作者，完整消费结果并按逻辑坐标核对，同时检查任务完成记录和耗时。

**Acceptance Scenarios**:

1. **Given** 存在多个可独立扫描的数据区间，**When** 允许多个工作者，**Then** 至少两个工作者实际处理数据，全部目标位置恰好覆盖一次；与串行查询的结果多重集合一致。
2. **Given** 只有一个小区间、工作者上限大于区间数量或空选择，**When** 并行查询，**Then** 正确结束，不重复处理位置、不死锁，空选择不产生值读取。
3. **Given** 并行查询中一个任务失败或用户取消，**When** 查询终止，**Then** 整体状态为失败或取消，停止后续任务并释放资源；之后的有效查询仍可成功。
4. **Given** 预先固定的适合并行的样本和环境，**When** 比较串行与并行完整查询，**Then** 结果一致，重复测量的并行耗时中位数更低，报告实际工作者数量及内存成本。

---

### User Story 5 - 复用读取并解释查询成本 (Priority: P2)

作为反复分析同一资料的用户，我希望缓存减少重复读取，同时能辨别筛选、并行和缓存各自是否生效，避免把旧数据或不完整统计当作性能收益。

**Why this priority**: 使远程重复分析更经济，并提供可复现的优化依据。

**Independent Test**: 在可验证版本的固定远程对象上执行关闭缓存、冷缓存、热缓存及清理后查询，并替换对象内容核对失效行为；同时运行并发查询验证记录隔离。

**Acceptance Scenarios**:

1. **Given** 内容未变且读取工作集可容纳于配置容量，**When** 同一会话重复查询，**Then** 热缓存结果与无缓存一致，实际远程读取字节或请求次数至少一项严格减少。
2. **Given** 用户关闭、清理或限制缓存容量，**When** 执行查询，**Then** 设置可验证地生效，容量不足时可继续正确查询，缓存占用不超过公布的容量上限。
3. **Given** 同一路径的对象已变化或当前用户不再有访问权限，**When** 再次查询，**Then** 不复用失效或未获授权的数据；无可靠版本判断时不跨查询复用对象缓存。
4. **Given** 全扫、局部、空选择、回退、串行、并行及冷/热缓存查询，**When** 查看各次运行记录，**Then** 可分别辨认读取量、网络传输、解码量、缓存收益、参与工作者、耗时、峰值内存和完成状态。
5. **Given** 两个并发查询，其中一个失败或取消，**When** 查看记录并继续查询，**Then** 统计按查询隔离，失败测量不标为成功，另一查询不受错误状态污染。

### Edge Cases

- 时间跨日、跨年及不同时区表示：绝对时刻统一按 UTC 解释；无时区输入按 UTC，拒绝不支持的日历和无法表示的时刻，不依赖运行机器时区。
- 坐标向量长度为一、递减、不等间隔、非单调或值重复；空轴、缺失坐标值及非有限数值坐标拒绝映射。重复坐标不能导致逻辑位置去重。
- lead_time 允许零及明确声明的负时长；level 的压力、高度、模型层编号不得在单位或层次类型未知时互相混用或转换。
- run、lead_time、time 分别映射已有轴；本期不自动构造 time = run + lead_time 的跨轴派生坐标，不从文件名猜测起报时间。
- 轴顺序变化、展平空间轴与多个非空间轴共存、跨输出批次、多变量证据冲突，以及原值列与新增语义列重名。
- 空间和非空间条件交集为空、NULL 比较、开闭边界、不受支持的表达式、无显式排序时的并行输出顺序变化。
- 远程重定向或访问错误、范围响应不匹配、短读、截断、对象替换，以及失败或取消后的再次查询。
- 缓存容量小于单次读取、淘汰后重读、并发读取同一对象、不同对象具有相似路径，以及缓存命中时权限变化。
- 全扫或小文件不能跳过块，不保证读取收益；并行任务过少或网络受限时不承诺加速，不选作收益验收样本。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持 time、level、lead_time、member、run 五类语义与现有逻辑轴的明确映射；接受完整显式声明或已识别且有文档依据的文件坐标证据，不从轴长度或路径猜测。
- **FR-002**: 映射 MUST 包含轴身份、坐标取值及必要的单位或类型；支持等间距定义和显式坐标序列。每种语义至多对应一个轴，每个轴至多对应一种上述语义，坐标数量必须等于轴长。
- **FR-003**: time 与 run MUST 表示 UTC 绝对时刻，lead_time 表示有明确单位的时长，level 表示带垂直类型和单位的数值，member 表示精确保留的整数或文本标识。输出含义、精度与可表示范围必须有文档，不允许有损截断或隐式单位猜测。
- **FR-004**: 系统 MUST 在返回数据前拒绝不完整或冲突映射、未知单位、非法坐标、列名冲突和不兼容多变量布局；用户能从错误定位涉及的轴或变量。显式声明不得覆盖相冲突的文件证据。
- **FR-005**: 语义列 MUST 按实际逻辑轴顺序与值对齐，保留单元素轴、重复坐标及所有未映射轴位置；未声明语义时保持原有 schema 和扫描行为，不自动转置、广播或连接变量。
- **FR-006**: 系统 MUST 对 time、run、lead_time、数值 level 的类型相容常量等值、大小比较及 BETWEEN，以及 member 等值和这些条件的安全合取，缩小候选位置；开闭边界遵循输出坐标的精确比较语义。
- **FR-007**: 维度筛选 MUST 与空间筛选、值过滤、列裁剪、计数、聚合、表达式和列重排组合，最终执行完整条件。不支持的条件或坐标排列允许安全回退，不能只取析取的一个分支而漏行。
- **FR-008**: 可凭坐标证明的空选择，以及无值依赖的坐标和计数查询，MUST 保持值索引读取、值数据读取和值块解码为零；未依赖变量不得解码。坐标与元数据成本必须单独计量。
- **FR-009**: 在预先固定且可跳过块的多维样本上，受支持的非空间局部筛选 MUST 同时减少值数据字节与解码块数，混合空间筛选结果必须与独立完整扫描基准一致。
- **FR-010**: 系统 MUST 支持单个 HTTP(S) 和 S3 OM 对象，沿用本地输入的格式子集、变量命名、映射、空间语义与缺测规则；可通过已有访问配置读取私有 S3 对象，错误和记录不得泄露凭据。
- **FR-011**: 支持局部读取的远程来源 MUST 按查询需要读取；在固定多块样本的冷缓存比较中，局部查询的实际响应数据总字节必须严格少于同列全扫。不得用预先完整下载制造局部读取的表象。
- **FR-012**: 不支持所需读取、不可访问、短读或读取失败 MUST 明确失败；标准文件接口取得的长度/版本证据冲突导致整次查询失败。逐响应协议验证依赖官方 HTTPFS，不承诺扫描快照。
- **FR-013**: 系统 MUST 提供可限制工作者数量的并行扫描，适用于本地及远程输入；串行与并行模式具有相同结果多重集合，每个目标逻辑位置恰好处理一次，无显式排序时不承诺输出顺序。
- **FR-014**: 存在足够可分割工作时 MUST 由多个工作者实际执行；任务少于工作者上限、空选择及跨批次输出必须正确完成。失败或取消必须终止后续任务、释放资源并允许随后有效查询。
- **FR-015**: 不提供 DuckOMO 跨查询范围缓存及缓存 SQL 项；上游缓存使用 DuckDB/HTTPFS 的标准行为和配置。
- **FR-016**: 对象须在扫描期间稳定。worker 打开比较可观察长度/版本，不承诺上游缓存即时撤权或强制新鲜探测。
- **FR-017**: MUST 按查询隔离记录自有选择、读取、解码、任务、终态和内存。官方远程 transport 指标为 NULL/complete=false，本地为 0/complete=true；legacy 自有 cache 为 false/0/removed。
- **FR-018**: 应用文件接口读取和服务端已发送量 MUST 分开；后者仅在验收侧审计。冷/重复查询记录上游配置，失败/取消不列为成功性能证据。
- **FR-019**: 交付 MUST 提供固定样本身份、独立坐标和值参考、可复现查询及正确性和成本证据，覆盖五类维度、维度顺序、混合谓词、空结果、三类来源、串/并行及缓存状态；至少一个真实 OM 样本完成本地与远程结果核对。
- **FR-020**: 用户文档 MUST 说明维度含义、映射证据、单位约定、远程访问前提、失败行为、并行与缓存控制、观测口径及限制，并同步 README、接口说明、技术架构和相应查询契约；依据证据更新路线图状态。

### Key Entities *(include if feature involves data)*

- **语义维度映射**：语义名称、原始轴身份、取值规则或坐标序列、单位/类型及来源证据；定义逻辑位置与用户坐标的关系。
- **逻辑记录**：多维数组中的一个位置及其值、空间和非空间坐标；不同位置可以具有相同坐标值。
- **查询选择**：完整用户条件及可安全缩小的候选位置，包含空选择和回退原因。
- **数据对象身份**：本地文件或远程对象的位置、内容版本和访问上下文；同一路径不等同于同一版本。
- **扫描任务**：查询中可独立完成的一组逻辑位置，具有归属查询、覆盖范围和完成状态。
- **缓存条目**：在限定容量与有效性范围内可复用的对象读取内容，具有身份、版本、访问上下文和占用量。
- **运行证据**：一次查询的配置、输入身份、结果核对及读取、解码、并行、缓存、耗时、内存和终止状态记录。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 五类维度分别通过独立坐标对照，至少覆盖两种不同轴顺序、等间距与非等间距坐标、单元素轴和重复坐标；所有验收查询的逻辑位置、坐标、值及缺测位置一致率为 100%。
- **SC-002**: 单维、空间与非空间合取、值过滤、复杂条件回退、开闭边界及空结果全部与完整扫描基准一致；至少一个固定多块样本的非空间局部查询同时严格减少值数据读取和解码量。
- **SC-003**: 本地、HTTP(S) 和 S3 三类来源的验收结果一致率为 100%，至少包含一个真实样本；两个远程来源均证明冷缓存局部查询的响应数据总字节严格少于同列全扫。
- **SC-004**: 全部可证明空选择和无值依赖坐标/计数用例的值索引、值数据及值块解码为零，混合查询中无关变量解码为零；必要坐标和元数据成本可单独辨认。
- **SC-005**: 至少以 1、2、4 个工作者上限完成本地和远程正确性核对，覆盖任务少于工作者数量与跨批次情况，零遗漏、零额外重复；至少一个事先选定且有足够工作的代表样本在同等缓存条件下各完成 5 次串行与并行测量，并行耗时中位数低于串行。
- **SC-006**: 官方路径固定对象的冷/重复查询完整结果一致，性能变化公开记录；标准接口可观察冲突及访问失败明确报错。旧自有缓存 G5 已替换，历史失败保留。
- **SC-007**: 所有非法映射、远程异常、对象变化、任务失败和取消验收用例均给出预期错误或终止状态，无成功返回的残缺结果；每类失败后都能再次成功完成有效查询，并发查询记录互不污染。
- **SC-008**: 未参与实现的验证者按交付说明完成维度筛选、官方远程局部查询、并行比较和冷/重复查询审计，正确判断实际优化及未知指标。

## Assumptions

- “Phase 4～5”指 [Roadmap](../../docs/roadmap.md) 的“其他维度”和“远程与并行”，不是已有 tasks.md 的内部编号。本次统一形成一个 feature，依赖已完成的 Phase 0–3。
- 输入仍是单个扫描期间不变的 OM 对象，格式、精度及多变量对齐沿用 [现有接口](../../docs/spec.md)；目录发现、glob、文件列表、跨文件拼接、写入及新增格式不在本期。
- 五类语义以一维轴映射为基线；各语义可以分开使用，未要求一个文件同时具有全部五类。跨轴有效时间推导、日历运算、垂直插值、集合统计等科学计算不属于本期。
- 未指定的时间规则采用 UTC；层次不自动换算或猜测，成员标识不自动重编号。完整语义描述的具体调用形式和类型契约由后续计划确定，但不能改变本文的含义及拒绝规则。
- 文件自动映射仅适用于有来源与样本核对的元数据约定；未识别文件可通过显式映射查询。后续计划必须列出实际支持的证据格式与单位，不能宣称识别任意元数据。
- 远程服务须可提供文件长度和可靠的局部读取，用户负责已有访问配置；本期不增加账户、凭据管理产品或离线同步能力。无法可靠跨请求验证版本的对象要求在扫描期间保持不变，公开说明这一限制；上游缓存行为不受 DuckOMO 的容量或即时撤权保证。
- 缓存默认以会话内复用为目标，不承诺跨进程持久化或离线访问；单次查询和并行任务内也可复用读取。容量与性能比较使用明确记录的配置，完整消费结果后再评估。
- 并行和读取收益使用事先固定的样本、环境、列集合与缓存状态验证，不对任意小文件、块布局或网络承诺加速比例。远程响应数据字节包含元数据等传输成本，但不含传输协议头开销。
- 延续当前 Linux AArch64 验收范围，Linux x86_64 支持与验证继续暂缓；Phase 6 的新网格与 Phase 7 的科学算子不纳入本期。
- [现有架构](../../docs/architecture.md) 的官方 OM reader 职责、逻辑选择边界和完整过滤约束由后续 plan 承接；本规格固定用户可观察的行为与验收结果，不指定新的内部实现。
