# Foundation verification

Date: 2026-09-29
Environment: Linux AArch64, DuckDB v1.5.4, release build. This foundation-only record is not full feature evidence; Linux x86_64 is deferred from the current scope.

The fixed-version callback gate passed using the commands recorded in [callback.md](callback.md). `spatial_callback_test` confirmed that exact humidity and coordinate filters remain above `READ_OM`, filter-only columns remain projected, integer and reversed comparisons bind as DOUBLE residuals, and callback invocation is recorded. It does not claim that any predicate reduces reads.

Foundation checks passed:

- `make release` completed successfully before adding the domain reference target. The target subsequently compiled successfully with `cmake --build build/release --target domain_reference_test -j2`.
- `build/release/test/unittest test/sql/spatial.test` passed 198 assertions.
- `regular_grid_test`, `spatial_layout_test`, `spatial_metrics_test`, and `spatial_callback_test` all passed.
- `scripts/validate.sh build/release` exited 0. It passed raw/read_om/projection SQL tests, the legacy native scanner checks, the projection evidence harness, 37 synthetic fixture/reference/negative hashes, deterministic fixture regeneration, and the separate pinned domain-manifest check.
- `projection_evidence_test` exercised failure and cancellation records and successful recovery. Failed or cancelled/incomplete metrics were excluded from successful performance comparisons.

The coordinate oracle is independent scalar arithmetic in `test/tools/spatial_reference.hpp`; value CSVs were generated by the pinned official OM C reader. The real-domain sample and all 15 reference hashes are pinned separately in `test/data/domain-manifest.json`; the real sample is not a regenerable synthetic fixture.

These checks clear the fixed DuckDB callback and shared-foundation gates only. They do not establish domain publication, spatial predicate extraction, or I/O reduction. The in-scope platform acceptance is recorded separately in [Linux AArch64 evidence](linux-aarch64.md); x86_64 is deferred from the current scope.
