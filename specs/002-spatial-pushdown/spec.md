# Feature Specification: Phase 3 规则网格空间下推

**Feature Branch**: `main`（当前分支；未配置分支创建 hook）

**Created**: 2026-09-29

**Status**: Implemented and independently verified on Linux AArch64; Linux x86_64 support and verification are deferred from the current scope by user decision

**Input**: User description: "Phase 3"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 用可信的经纬度查询规则网格 (Priority: P1)

作为气象数据分析者，我希望为本地 OM 文件指定已知 domain 或明确的规则经纬度网格，并获得每个值对应的经纬度，以便直接开展区域分析，无需预先转换文件。

**Why this priority**: 正确的坐标和值对应关系是空间过滤可信的前提。

**Independent Test**: 为有独立参考坐标和值的非方形样本指定网格，查看列描述并扫描全部点，逐位置核对坐标、数值及多变量对齐。

**Acceptance Scenarios**:

1. **Given** 受支持的本地文件及完整显式规则网格配置，**When** 用户查看列描述并查询，**Then** 得到稳定的 latitude、longitude 列，各逻辑位置的坐标与独立参考一致，值和缺测位置保持不变。
2. **Given** 一个已核对来源的受支持 domain 及匹配文件，**When** 用户按 domain 查询，**Then** 坐标和值与使用等价显式配置时一致，用户可查到网格定义的来源及适用布局。
3. **Given** 分离的两个空间轴或按明确顺序展平的空间轴，且文件还含其他轴，**When** 用户正确声明空间轴对应关系，**Then** 每个其他轴位置都对应正确的地理点，不交换或遗漏记录；其他轴不自动获得时间等语义。
4. **Given** 未指定网格或 domain，**When** 用户执行已有值查询，**Then** 延续既有行为；请求不存在的经纬度列明确失败，不从文件名或 shape 猜测地理位置。
5. **Given** 未知 domain、非规则网格、冲突配置、形状不匹配或不明确的空间轴对应关系，**When** 用户请求坐标扫描，**Then** 在返回数据前明确拒绝并说明原因。

---

### User Story 2 - 查询小区域时减少实际读取 (Priority: P1)

作为只关注某个区域的分析者，我希望经纬度条件既给出正确结果，也减少读取与解码工作，而不必自己计算数组索引。

**Why this priority**: 这是路线图中 Phase 3 的核心价值和退出条件。

**Independent Test**: 在空间上跨多个可独立读取块的固定样本中，比较全域读取后过滤的独立基准与小区域查询，核对结果及实际读取字节、解码块数。

**Acceptance Scenarios**:

1. **Given** 跨多个空间块的样本，**When** 用户以经纬度常量上下界的合取选择小区域，**Then** 结果与全域基准过滤结果完全一致，变量数据字节数和解码块数均严格少于同列全域查询。
2. **Given** 仅纬度或仅经度存在等值或范围条件，**When** 用户查询，**Then** 另一方向保持全范围，所选记录与完整扫描后过滤一致。
3. **Given** 区域边界落在网格点上或两个点之间，**When** 用户分别使用包含和排除边界的比较，**Then** 精确遵守条件，不遗漏边界点，也不返回仅因候选范围扩大而纳入的点。
4. **Given** 条件互相矛盾或区域不与网格相交，**When** 系统可仅凭网格定义和支持的空间条件确定空结果，**Then** 返回零行，值数据读取和解码均为零。
5. **Given** 非空区域条件且只查询坐标或行数，**When** 无其他值变量依赖，**Then** 坐标或计数正确，不读取或解码值变量。

---

### User Story 3 - 将区域过滤与现有分析组合 (Priority: P2)

作为分析者，我希望区域选择能与变量选择、值过滤和聚合一起使用；较复杂的地理条件也必须得到正确结果，并能辨认是否真正减少了读取。

**Why this priority**: 保证新优化可用于实际分析，延续已有列裁剪能力。

**Independent Test**: 在多变量固定样本上组合地理过滤、额外值过滤、聚合及跨经线条件，并与无空间优化的基准结果比较。

**Acceptance Scenarios**:

1. **Given** 输出变量 A、以变量 B 过滤且带区域条件的查询，**When** 执行查询，**Then** A 和 B 正确对齐，未依赖变量不被解码；结果与全域基准一致。
2. **Given** 查询重排或重复引用列、计算表达式、排序或聚合，**When** 加入区域条件，**Then** 查询语义、缺测规则及计数保持正确，未输出的过滤列仍可用于精确判定。
3. **Given** 跨越经度接缝的目标区域，**When** 用户按公布的经度约定用两个区间的并集表达条件，**Then** 无遗漏或额外重复的逻辑位置；普通下界大于上界的 BETWEEN 条件仍为空，不隐式解释为跨经线。
4. **Given** 不能安全缩小读取的复杂表达式或含不支持分支的析取条件，**When** 执行查询，**Then** 保留精确过滤且与全域基准一致，并在验证记录中标明回退；不得用不安全的局部范围排除匹配行。
5. **Given** 同一数据上的全域、小区域、空区域和回退查询，**When** 验证者查看运行记录，**Then** 可对比实际读取、解码、耗时及峰值内存，并区分优化生效、空选择和回退。

### Edge Cases

- 负向纬度或经度步长、非方形网格、单行或单列网格、极点，以及恰落在点上或相邻浮点值处的边界。
- 原始经度以 0–360 或 -180–180 表示，以及经度序列跨接缝；输出采用同一公布约定，过滤按输出坐标解释。
- 若源数据同时存有接缝两端的逻辑点，保留各自记录；优化不能额外重复同一逻辑位置，也不能按相同经纬度擅自去重。
- 不同空间轴顺序、展平空间轴和额外非空间轴；同 shape 不能证明空间身份一致。
- 网格大小为零、步长为零或非有限数、纬度越界、空间大小不匹配及空间轴声明缺失均拒绝。
- 源变量名与 latitude 或 longitude 冲突时，坐标模式明确拒绝，不静默覆盖已有变量。
- 常量假条件、NULL 比较、无穷或非有限边界及混合 AND/OR 条件遵守查询本身语义；不能证明安全时回退。
- 全域查询或小于一个物理块的文件不保证节省读取；不得把这种情况计为性能验收样本。
- 跨多个输出批次、值缺测、文件损坏和查询取消不产生错位或成功返回的残缺结果；失败后可再次执行有效查询。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在现有本地 OM 支持子集上支持规则经纬度网格，允许显式配置或选择已验证的命名 domain；两者同时提供时明确拒绝，避免隐式优先级。
- **FR-002**: 显式配置 MUST 足以确定两个方向的点数、首点坐标、有符号步长、空间轴身份及存储顺序；支持两个独立空间轴和单个展平空间轴。不能唯一对应文件逻辑位置时必须拒绝。
- **FR-003**: 系统 MUST 在返回行前验证网格和变量布局一致性，拒绝未知或不支持 domain、无效参数、矛盾的轴证据、形状不匹配以及坐标列命名冲突；不能只凭相同 shape 或路径推断映射。
- **FR-004**: 可靠网格配置下 MUST 暴露 latitude、longitude，并保持每行坐标与值的逻辑位置一致。纬度为角度值且位于 [-90, 90]，输出经度统一为 [-180, 180)；源经度约定不改变输出和过滤含义。坐标误差容差须在验证前记录。
- **FR-005**: 没有网格配置时 MUST 延续已有原始值扫描、列名、变量对齐及缺测行为，不新增猜测坐标；已有语义坐标缺失错误仍明确可见。
- **FR-006**: 系统 MUST 将 latitude、longitude 与有限常量的等值、大小比较、BETWEEN 及其合取用于缩小空间读取范围；支持单轴筛选、双轴矩形及开闭边界，不要求用户直接提供逻辑索引。
- **FR-007**: 空间优化 MUST 保留最终条件的精确语义，不能遗漏合格记录或返回候选范围多包含的记录；不安全或未支持的表达式必须正常回退。析取条件不得只考虑其中一个分支。
- **FR-008**: 跨接缝区域 MUST 能用两个经度区间的并集正确查询；本阶段不要求该并集减少物理读取。下界大于上界的普通区间遵循正常比较语义，不自动环绕。
- **FR-009**: 可根据支持的空间条件确定的空选择 MUST 不读取值数据、不解码值块；坐标或纯空间计数查询无值依赖时也必须不读取或解码值变量。允许必要的文件元数据读取。
- **FR-010**: 空间筛选 MUST 与已有变量裁剪协同，保留输出和过滤等全部依赖，无关变量解码为零；表达式、排序、聚合、列重排、重复引用及缺测规则不得改变。
- **FR-011**: 空间筛选 MUST 应用于每一个非空间逻辑位置，保持多变量对齐且不做隐式广播；额外轴保留原始逻辑语义，不新增时间、层次或预报维度映射。
- **FR-012**: 系统 MUST 提供可复现的全域、小区域、空区域及回退验证记录，包含查询、样本身份、网格来源、结果核对、实际读取字节数、读取请求数、解码块数、耗时和峰值内存；区分值数据与元数据等开销，并说明空间优化是否生效。
- **FR-013**: 在事先固定、具有可跳过空间块的样本上，小区域查询 MUST 比相同值列的全域查询读取严格更少的值数据字节并解码严格更少的块；仅减少输出行数不能通过验收。
- **FR-014**: 首批 domain MUST 至少包含一个与上游定义及真实本地文件核对的规则经纬度网格，公布来源版本、适用布局和验证证据；未经验证的 domain 不得宣称支持。测试坐标参考必须独立于待测坐标生成结果。
- **FR-015**: 系统 MUST 提供可复现使用说明，覆盖显式网格、domain、坐标约定、跨经线写法、空间轴布局、支持条件、回退和错误；用户可据此完成区域查询及结果核对。新增用户语义须同步到项目产品文档。
- **FR-016**: 查询失败或取消 MUST 释放资源，不把残缺结果或失败测量计为正确性或性能成功；随后有效查询仍能成功。

### Key Entities *(include if feature involves data)*

- **规则经纬度网格**：两个方向等间距的地理点集合，具有点数、首点坐标、步长和经度约定。
- **Domain 定义**：带名称及可追溯来源的已验证网格描述，并注明适用文件布局；不代表自动发现或下载文件。
- **空间轴对应关系**：文件逻辑轴与网格行列或展平点的关系，决定每条值记录的坐标。
- **空间条件与选择**：用户指定的坐标条件及其对应的候选逻辑位置；最终结果仍满足完整精确条件。
- **参考样本与观测记录**：固定本地数据、独立坐标和值参考，以及可复现的正确性和实际读取证据。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 显式网格与至少一个已验证 domain 的坐标和值对照检查通过率为 100%；所有比较使用预先记录的容差，行数、缺测位置与逻辑位置对应完全一致。
- **SC-002**: 验收集覆盖非方形网格、反向轴、单点方向、两类空间布局、额外轴、接缝、边界、空区域及跨批次；小区域与全域基准过滤的结果一致率为 100%。
- **SC-003**: 至少一个固定多变量且跨空间块样本上，小区域查询的值数据字节数和解码块数均严格小于相同列全域查询，并具有完整的测量记录。
- **SC-004**: 可确定的空空间选择、仅坐标查询和纯空间计数三类场景的值数据读取及解码均为零；混合值过滤查询中，无关变量解码为零。
- **SC-005**: 支持条件、复杂条件回退、跨经线并集、值过滤、聚合及列裁剪组合均与独立基准一致；负向配置用例全部明确拒绝，无静默错误坐标，失败或取消后可成功查询。
- **SC-006**: 一名未参与实现的验证者可仅按交付说明完成显式网格查询、domain 查询和区域结果核对三项任务，并从记录判断是否节省读取，无需预转换文件或手工计算索引。

## Assumptions

- “Phase 3”依据 [Roadmap](../../docs/roadmap.md) 的 Spatial pushdown，而非既有 tasks.md 中的任务分组编号；产品范围沿用 [产品 Spec](../../docs/spec.md)，实现职责约束由 [架构](../../docs/architecture.md) 交给后续 plan 承接。
- Phase 0–2 及其真实文件兼容修复为依赖；本阶段继续面对单个、扫描期间不变的本地文件。本期验收平台为 Linux AArch64；Linux x86_64 支持与验证暂缓，不从 AArch64 证据推断其兼容性。
- 首批命名 domain 已固定为经上游和真实样本核验的 `ncep_gfswave025`；只支持 manifest 公布的 shape/轴布局，不承诺全部 Open-Meteo domain。用户提供的显式网格仍需满足同样的布局校验。
- 显式配置的具体调用形式由计划确定；此处固定用户需要表达的信息与错误行为。既有 dimensions 轴声明不自动等价于完整地理网格配置。
- 经度统一为 [-180, 180)、配置二选一以及坐标列冲突时拒绝，是为未指定细节采用的默认规则；坐标比较依据输出值，不添加改变查询语义的隐式容差。
- 对非空间轴仅保持所有原始位置；时间、level、lead_time、member、run 映射及下推属于 Phase 4。HTTP/S3、并行与缓存优化属于 Phase 5，Gaussian 和投影网格属于 Phase 6，插值与科学计算属于 Phase 7。
- 性能比较使用相同文件、列集合、运行环境及明确的缓存条件；测试区域须能跳过空间块，不对所有小区域或所有文件承诺读取比例，也不凭空设定耗时阈值。
- 独立坐标参考来自经核对的上游网格定义或人工确认的固定样本；值参考来自官方读取结果。真实样本须记录来源与内容身份，验证期间不依赖远程扫描能力。
- 当前 constitution 仍为未填写模板，不把示例原则视为已批准规则。
