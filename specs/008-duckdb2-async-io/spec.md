# Feature Specification: DuckDB 2.0 正式支持、远程读取请求合并与异步 I/O

**Feature Branch**: `main`（仅规格，未切换分支）

**Created**: 2026-10-23

**Status**: Draft

**Input**: User description: "支持2.0 同时CI增加duckdb 2.0插件的发布，实现合并请求， 以及针对2.0的异步I/O 提供支持和优化"

## 背景

2026-10-23 的实验评估（[docs/duckdb-2.0-evaluation.md](../../docs/duckdb-2.0-evaluation.md)）表明：

- DuckOMO 已能在 DuckDB 2.0 上本地编译并通过 SQL、受控远程（48 项）与取消/隔离检查，但改动未提交，没有 2.0 发布产物，CI 和支持矩阵只覆盖 1.5.4–1.5.6。
- 在固定真实对象（ECMWF O1280 地形，4,087,256 字节）上，升级到 2.0 对远程读取**没有提速**：两版本请求数与字节完全相同。
- 远程耗时由请求数量主导：读完该对象需约 11,592 次范围请求（平均约 356 字节/次）。单 worker 下 loopback HTTP 约 6.4 秒、S3 约 15.8 秒，本地仅 0.17 秒。

本特性把实验性兼容变为正式支持，并通过"减少请求次数"和"让请求并发在途"两条路径改善远程读取。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在 DuckDB 2.0 上安装并使用 DuckOMO (Priority: P1)

使用 DuckDB 2.0 的用户希望像在 1.5.x 上一样，通过标准发布渠道获取与 2.0 匹配的 DuckOMO 扩展，加载后所有现有查询（read_om、区域统计、nearest/bilinear 采样、网格信息、远程 HTTP/HTTPS/S3 读取）照常工作、结果不变。

**Why this priority**: 没有可安装的 2.0 产物，用户无法在新版引擎上使用 DuckOMO；这是其余优化能交付到用户手里的前提。

**Independent Test**: 从 CI 发布产物（不是本地编译）取得 2.0 扩展，在对应官方 DuckDB 2.0 运行时上加载，跑完整回归与受控远程验收，结果与 1.5.6 同查询一致。

**Acceptance Scenarios**:

1. **Given** 一个打了发布标签的版本，**When** CI 发布流程运行，**Then** 同时产出 1.5.4、1.5.5、1.5.6 与 2.0.0 各自匹配的扩展产物，且每个产物都在对应官方引擎上通过加载与运行时检查。
2. **Given** 用户使用 DuckDB 2.0，**When** 加载 2.0 产物并执行现有文档中的查询，**Then** 结果与 1.5.6 同查询一致，SQL 接口、参数、返回列与错误类别不变。
3. **Given** 用户误用 1.5.x 产物加载到 2.0（或反之），**When** 尝试加载，**Then** 得到明确的版本不匹配提示，而不是崩溃或错误结果。
4. **Given** 维护者提交代码，**When** 日常 CI 运行，**Then** 2.0 与所有 1.5.x 版本都编译并通过回归；任一版本失败都会阻止合并。

---

### User Story 2 - 远程读取时显著减少请求次数 (Priority: P2)

从 HTTP/HTTPS/S3 读取 OM 文件的用户，希望同样的查询发出的请求大幅减少，从而在高延迟对象存储上更快完成，同时不明显多读无用数据。

**Why this priority**: 实测远程耗时主要来自小请求的往返次数。减少请求次数不依赖引擎版本，1.5.x 与 2.0 用户都能受益，且风险低于异步改造。

**Independent Test**: 在受控远程服务上对固定真实对象执行全扫与局部选择查询，比较服务端记录的请求数、发送字节、耗时与结果，开启/关闭该能力各测一次。

**Acceptance Scenarios**:

1. **Given** 固定真实对象与全扫查询，**When** 通过远程读取，**Then** 服务端请求数相比当前基线显著下降，结果与本地读取完全一致。
2. **Given** 只选择一小块区域或少量时间步的查询，**When** 通过远程读取，**Then** 服务端发送字节不超过当前基线的规定上限，局部读取相对全扫的字节收益仍然成立。
3. **Given** 用户需要旧行为以排查问题，**When** 关闭该能力，**Then** 请求模式回到当前基线，结果相同。
4. **Given** LIMIT 查询或中途取消，**When** 远程读取，**Then** 多读的数据量有明确上限，取消后及时停止并释放资源。

---

### User Story 3 - 在 DuckDB 2.0 上让远程读取并发在途 (Priority: P3)

在 DuckDB 2.0 上读取远程 OM 的用户，希望等待网络的时间不再占住计算线程：多个读取请求同时在途，计算线程在等待期间继续做解码等工作，从而在高延迟存储上进一步缩短耗时。

**Why this priority**: 收益依赖 2.0 引擎能力和 Story 2 的成果，改造面最大、风险最高，放在最后。

**Independent Test**: 在 DuckDB 2.0 上，对同一远程对象与查询分别以异步开启/关闭运行，比较耗时、在途请求并发度、计算线程忙碌情况、内存峰值与结果。

**Acceptance Scenarios**:

1. **Given** DuckDB 2.0 与远程对象，**When** 开启异步读取，**Then** 同时在途的请求数大于 1，耗时低于同版本关闭异步时，结果完全一致。
2. **Given** 内存受限的会话，**When** 开启异步读取，**Then** 预读数据量随内存预算收缩，查询不会因预读而内存溢出，在紧张时退化为接近同步读取。
3. **Given** 用户在 1.5.x 上运行，**When** 执行相同查询，**Then** 行为与同步路径一致，不出现错误。
4. **Given** 异步读取过程中发生网络错误、权限变化、对象版本变化或用户取消，**When** 查询结束，**Then** 错误类别、脱敏规则、取消状态和同连接恢复与同步路径一致，没有遗留在途请求或泄露内存。

---

### Edge Cases

- 对象很小（只有几个 chunk）或只有元数据：合并与预读不得增加请求数或读取量。
- 被选中的数据在文件中高度分散：合并必须受间隙上限约束，避免读入大量不需要的中间字节。
- 远程服务不支持范围请求、返回短读、或中途对象版本变化：与现有同步路径一样明确失败，不返回混合版本数据。
- 多个 worker、多个连接同时读取同一对象：各自结果正确，计量互相隔离。
- 合并后的单次请求超过服务端或引擎对单次读取大小的限制：需要拆分。
- 异步在途请求尚未完成时查询被取消或连接关闭。
- 同一进程中加载多个 DuckDB 实例，后台读取线程总数与内存需可控。
- DuckDB 2.0 发布渠道或社区构建工具链尚未提供某个平台时：该平台产物缺失必须显式报告，不能静默跳过。

## Requirements *(mandatory)*

### Functional Requirements

**DuckDB 2.0 支持与发布**

- **FR-001**: 同一份源码 MUST 能为 DuckDB 1.5.4、1.5.5、1.5.6 与 2.0.0 分别构建匹配的扩展，现有 1.5.x 行为不回退。
- **FR-002**: 2.0 产物 MUST 在对应官方 DuckDB 2.0 运行时及其官方 HTTPFS、spatial 扩展上通过完整回归、受控远程验收、取消/连接隔离检查与内存/线程错误检查。
- **FR-003**: 日常 CI MUST 为每次提交构建并测试 2.0 与全部 1.5.x 目标；任一失败阻止合并。
- **FR-004**: 标签发布流程 MUST 为 2.0.0 产出可分发的扩展产物，平台集合与当前 1.5.6 发布范围一致；每个产物在匹配的官方引擎上校验后才发布。
- **FR-005**: 支持矩阵文档、README 与本仓库发布说明 MUST 列出 2.0.0，并说明每个产物只对应一个引擎版本。社区扩展登记不在本特性范围内（见 Assumptions）。
- **FR-006**: 2.0 与 1.5.6 上相同查询 MUST 返回相同结果；因上游引擎修复导致的差异（如 FLOAT→DECIMAL 精度修复）MUST 在发布说明中记录。

**远程读取请求合并（1.5.x 与 2.0 均适用）**

- **FR-007**: 远程读取 MUST 将同一对象中相邻或间隙较小的待读范围合并为更少的请求，并把结果正确分发给各自的使用方。
- **FR-008**: 合并 MUST 受可配置的上限约束：单次请求最大字节数、可吞并的最大间隙字节数；默认值 MUST 在固定样本上验证读放大不超过规定比例。
- **FR-009**: 用户 MUST 能通过会话设置关闭合并，恢复当前请求模式。
- **FR-010**: 本地文件读取的行为与结果 MUST 不受影响。
- **FR-011**: 远程扫描指标 MUST 报告请求次数、实际传输字节与"有用字节"（选择所需数据的字节数），二者之差即合并引入的多读字节；这些值对每次远程扫描都必须可得。

**DuckDB 2.0 异步 I/O**

- **FR-012**: 在 DuckDB 2.0 上，远程 OM 读取 MUST 能把网络等待交给引擎的异步执行机制，使计算线程在等待期间可处理其他工作。
- **FR-013**: 异步读取 MUST 限制同时在途的请求数与字节数；该上限 MUST 随会话可用内存动态收缩，内存紧张时退化为一次一个请求，压力解除后恢复。
- **FR-014**: 用户 MUST 能通过会话设置关闭异步读取，回到同步路径；1.5.x 构建始终走同步路径。
- **FR-015**: 异步路径的错误分类与脱敏、取消、对象身份校验、访问权限检查、每 worker 状态隔离与查询结束指标 MUST 与同步路径一致。
- **FR-016**: 取消或出错时 MUST 释放全部在途请求与缓冲，不得在查询结束后仍有后台读取。

**验证与证据**

- **FR-017**: MUST 提供可复跑的版本/模式对比基准，覆盖全扫、局部选择、坐标-only、polygon、nearest，至少包含本地、受控 HTTP、受控 S3，并记录耗时分布、请求数、传输字节、内存峰值与结果校验。
- **FR-018**: MUST 至少在一个真实云对象存储端点上记录首读与重复读结果；不得用 loopback 数据推断云端收益。

### Key Entities

- **引擎目标（Engine Target）**：一个受支持的 DuckDB 版本与平台组合，关联其官方运行时、官方依赖扩展、构建身份与验证结果。
- **发布产物（Release Artifact）**：针对单一引擎目标构建的扩展文件及其校验摘要、构建来源与验证记录。
- **读取计划（Read Plan）**：一次扫描中对某个对象待读字节范围的集合，以及合并后的实际请求、间隙与分发关系。
- **读取预算（Read Budget）**：限制合并大小、间隙、在途请求数与预读字节的约束，部分来自用户设置，部分来自引擎内存状态。
- **扫描指标（Scan Metrics）**：每次查询的逻辑字节、传输字节、请求次数、读放大、在途并发峰值与终态。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 一次标签发布同时产出 4 个引擎版本（1.5.4、1.5.5、1.5.6、2.0.0）的扩展产物，每个产物 100% 通过其匹配运行时校验。
- **SC-002**: 2.0 产物通过与 1.5.6 相同的全部回归与远程验收项（当前为 21 个 SQL 用例、48 项远程检查、native 取消/隔离、内存/线程检查），失败数为 0。
- **SC-003**: 对固定真实对象（O1280，4 MB）全扫，开启合并后远程请求数比当前基线（约 11,592 次）至少减少 90%，且服务端发送字节不超过基线的 110%。
- **SC-004**: 对局部选择查询，开启合并后发送字节不超过当前基线的 125%，并且仍明显少于全扫。
- **SC-005**: 对固定真实对象，在受控 S3 上单 worker 全扫耗时比当前基线（约 15.8 秒）至少缩短 70%。
- **SC-006**: 在 DuckDB 2.0 上，开启异步后同一远程查询耗时比同版本仅开启合并时进一步缩短至少 20%，结果完全一致。
- **SC-007**: 在规定的内存上限下（如 256 MB）运行远程全扫，开启异步不导致内存溢出，进程峰值内存不超过关闭异步时的 1.5 倍。
- **SC-008**: 取消测试中，100% 的查询在取消后 1 秒内结束，结束后无在途请求、无内存账本残留。
- **SC-009**: 本地文件读取耗时与结果相对当前版本无回退（中位数差异不超过 5%）。

## Assumptions

- 发布平台集合沿用当前 1.5.6 的发布工作流范围；某平台的上游 2.0 工具链或官方扩展若不可用，该平台暂缺并在发布记录中说明，不阻塞其余平台。
- 继续同时支持 1.5.4–1.5.6，不在本特性中停止对 1.5.x 的发布。
- 社区扩展登记（duckdb/community-extensions）本特性不改，仍面向 1.5.6；2.0 产物通过本仓库 tag 发布提供。切换登记属于单独的发布决策。
- 请求合并默认开启，异步读取在 2.0 上默认开启；两者均提供关闭开关。若验证阶段发现默认开启的风险，默认值可调整，但开关必须保留。
- 异步读取只针对远程 HTTP/HTTPS/S3；本地文件维持现有同步路径。
- 不引入应用层持久缓存，也不改变既有的 DIRECT_IO、禁止整体下载、对象版本校验等远程读取策略。
- VARIANT shredding、Parquet 导出与 spatial 计算优化不在本特性范围内。
- 受控远程验收继续使用现有 fixture HTTP/HTTPS 服务与 S3 审计代理；真实云端点测试需要具备读取权限的公开或测试对象。
- 依赖：DuckDB 2.0.0 官方 CLI、HTTPFS、spatial 产物，以及与 2.0 匹配的社区扩展构建工具链。
