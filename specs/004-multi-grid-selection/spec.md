## User Scenarios & Testing *(mandatory)*

### User Story 1 - 用同一地理坐标语义查询不同网格 (Priority: P1)

作为气象分析者，我希望为单个 OM 文件明确选择网格定义，查询规则经纬度、旋转经纬度、Lambert、stereographic 和 Gaussian N 网格的数据，得到可信的经纬度与原始值，无需预转换成统一网格。

**Why this priority**: 坐标和值对应正确，才有可靠的区域查询和后续空间分析。

**Independent Test**: 每类新网格使用具有独立坐标及官方解码值参考的固定样本，分别声明显式网格和等价 domain，完整读取并核对位置、坐标、值和缺测。

**Acceptance Scenarios**:

1. **Given** 四类新网格的完整定义和匹配文件，**When** 查看列描述并读取，**Then** 既有值列及维度列保持含义，`latitude`、`longitude` 对应同一源位置；显式定义与等价 domain 结果一致。
2. **Given** 分离的投影空间轴、明确顺序的展平轴、反向轴或额外时间/层次/成员轴，**When** 读取，**Then** 所有源位置正确对应坐标，不假定真实纬度只依赖一个空间轴，或经度只依赖另一个空间轴。
3. **Given** N160、N320 的不等长纬度行及其完整展平点序，**When** 查询赤道附近、极区、行边界和接缝，**Then** 坐标和值正确对应，不补齐矩形、插入不存在的点或按重复经纬度去重。
4. **Given** 有完整区域映射证据的 Gaussian N 原生区域子集，**When** 查询，**Then** 使用该对象的局部点序与实际覆盖；不能按全域点偏移解释子集数据。
5. **Given** 缺少投影参数、地球模型、Gaussian 行定义或明确空间布局，或存在冲突证据，**When** 请求地理坐标，**Then** 返回数据前拒绝并定位问题；shape、路径和地理包围盒均不能代替完整定义。
6. **Given** 既有规则网格或未声明空间配置的查询，**When** 运行原查询，**Then** schema、规则坐标、语义维度、值及缺测行为符合原契约。

### User Story 2 - 将经纬度范围用于安全的区域选择 (Priority: P1)

作为只关心某个区域的分析者，我希望直接使用经纬度条件，在不同网格上筛出相同地理含义的点，并缩小后续读取范围，无需自行提供网格索引或文件字节位置。

**Why this priority**: 新网格必须带来可用的区域查询，且优化不能漏掉边界或投影曲线上的点。

**Independent Test**: 对每类网格，将区域查询与完整扫描后执行相同条件的基准按源位置核对，覆盖边缘、接缝、奇点附近及与其他维度的交集。

**Acceptance Scenarios**:

1. **Given** 有限常量的等值、大小比较、BETWEEN 及安全合取，**When** 筛选一个或两个地理坐标，**Then** 选择覆盖全部匹配位置的候选；最终结果与全扫过滤一致。
2. **Given** 地理矩形在投影空间中具有弯曲边界，或矩形角点在网格外但中部与网格相交，**When** 查询，**Then** 不以角点范围或角点越界断言无交集，不漏掉中部或边缘的合格点。
3. **Given** 明确的纬度条件与两个有限经度区间的安全并集，**When** 查询跨经线区域，**Then** 全部匹配源位置恰好出现一次；能够安全表达该并集时缩小候选，不能安全处理的其他析取保留完整条件并扩大候选。
4. **Given** 开闭边界、恰落在输出坐标或相邻可表示数值上的边界，**When** 查询，**Then** 按实际输出坐标精确比较，不用参考坐标的验证容差修改筛选语义。
5. **Given** 空间条件与 time、run、lead_time、level、member 或值过滤组合，输出变量与过滤变量不同，**When** 查询、计数或聚合，**Then** 所有条件正确生效、多变量不发生错位，无关值变量不被解码。
6. **Given** 无法证明安全的投影边界、函数、转换、复杂析取或碎片过多的选择，**When** 查询，**Then** 正常扩大候选或全扫，保留精确过滤，并记录具体回退原因。

### User Story 3 - 在 S3 和 HTTP 上真正减少局部读取 (Priority: P1)

作为远程气象资料的使用者，我希望对新网格执行区域查询时，只传输所需的元数据、坐标证据和压缩数据部分，避免先下载整个对象；本地和远程结果具有相同含义。

**Why this priority**: 地理选择只有传递到实际读取后才能节省网络成本，读取量不能用结果行数代替。

**Independent Test**: 每类新网格固定一个有可跳过空间块的样本，在本地、受控 HTTP(S) 和 S3-compatible 存储运行同列全扫与窄区域查询，关闭缓存，完整消费结果，核对服务端和查询记录。

**Acceptance Scenarios**:

1. **Given** 三类来源中的同一对象内容和网格声明，**When** 执行相同全扫与区域查询，**Then** schema、源位置、坐标、值与缺测位置一致。
2. **Given** 可跳过块的窄区域，**When** 冷态查询，**Then** 值数据读取、值块解码和实际远程响应 body 总字节均严格少于同列全扫；不预下载整文件或全域逐点坐标表后制造局部读取收益。
3. **Given** 地理区域对应多个不连续逻辑片段，且一个压缩块覆盖多个候选点，**When** 读取，**Then** 允许必要的块内多读，结果仍精确；地理点数不被解释为可直接计算的文件字节数。
4. **Given** 区域与时段联合筛选，空间轴不在数组末尾或对象为 Gaussian 区域子集，**When** 远程查询，**Then** 读取来自该对象正确的原始位置，不发生轴交换或全域/局部偏移混用。
5. **Given** 范围响应无效、短读、无权限、可检测的版本改变、取消或配套远程能力不匹配，**When** 查询，**Then** 明确失败或取消，不成功返回拼接/残缺结果，不静默完整下载；后续有效查询仍可成功。
6. **Given** 稳定对象的重复查询，或对象/访问权限改变，**When** 使用已有缓存，**Then** 结果符合原缓存有效性规则；网络收益可与地理选择收益分别辨认。

### User Story 4 - 只查询位置或空区域时避免读取值 (Priority: P1)

作为检查覆盖范围或统计网格点的用户，我希望仅查询坐标、按坐标计数或选择确定为空的区域时，不支付气象值的读取与解码成本。

**Why this priority**: 延续列裁剪与零值读取能力，避免新网格初始化隐藏全域值扫描。

**Independent Test**: 每类新网格运行全域和局部坐标查询、坐标条件计数、可证明空选择及含值过滤的对照查询，核对结果与各类成本。

**Acceptance Scenarios**:

1. **Given** 无值依赖的坐标查询或计数，**When** 查询任一受支持网格，**Then** 值索引读取、值数据读取和值块解码均为零，必要网格/坐标证据成本单列。
2. **Given** 坐标矛盾条件或可证明与网格不相交的区域，**When** 查询，**Then** 返回零行且上述三类值成本为零；无法证明为空时保持保守候选。
3. **Given** 同一空间点在多个非空间位置出现，**When** 计数，**Then** 按原始逻辑记录计数；不把气象记录数替换为去重后的地理点数。
4. **Given** 大网格或长时间轴，**When** 查询坐标或窄区域，**Then** 不要求预先保存全域坐标、候选行或全部任务；工作内存遵守已公布的上界。

### User Story 5 - 为后续空间计算保留可靠的网格身份 (Priority: P2)

作为后续空间分析和科学计算功能的使用者，我希望读取的数据仍能解释它来自哪个网格、哪个原始点、哪个坐标参考系，以便开展点与区域关系判断，并在切片、归约、插值或重网格时采用正确的空间含义。

**Why this priority**: 仅有经纬度无法恢复不等长行、投影空间距离、邻接关系或单元面积；这些信息需要从本期开始保持可追溯。

**Independent Test**: 获取每类网格的描述及明确请求的源位置身份，按原始点重建坐标；在一致且明确的坐标参考系中，将点与固定区域作精确关系判断，并与全扫后判断的基准核对。

**Acceptance Scenarios**:

1. **Given** 已绑定的网格，**When** 请求网格描述与源位置身份，**Then** 可取得定义版本、地球模型/坐标参考系、轴顺序、单位、点序和区域映射；默认读取列不因这些信息改变。
2. **Given** 输出子集被排序、过滤或并行产生，**When** 使用明确取得的源位置，**Then** 能恢复原始点身份及其非空间位置，不能用输出行号或经纬度去重替代身份。
3. **Given** 点与区域关系计算采用相同、明确的坐标参考系，**When** 构造位置并执行精确判定，**Then** 经度作为水平第一个坐标、纬度作为第二个坐标，结果与完整源点基准一致；区域包围盒只作为保守候选。
4. **Given** 未来消费者请求邻接、单元边界、面积、距离或向量方向含义，**When** 查看网格描述，**Then** 区分已定义、尚不支持和无法从源证据确定的能力；不默认等面积、等距离或地理正北，也不伪造 Gaussian 矩形邻居。
5. **Given** 当前只需普通数值扫描，**When** 查询，**Then** 不要求加载空间计算功能或执行隐式插值、重采样、向量旋转；读取仍代表原生点值。

### User Story 6 - 升级到 DuckDB 2.0 后继续使用同一查询语义 (Priority: P2)

作为维护查询应用的用户，我希望本期网格声明、地理筛选、远程访问和观测语义能够延续到 DuckDB 2.0，并明确知道当前版本组合有哪些实际验收证据。

**Why this priority**: DuckDB 2.0 是用户明确要求的后续兼容目标；网格扩展不能把产品契约绑定在仅适用于当前版本的行为上。

**Independent Test**: 在计划指定并固定身份的现有基线、2.0 预发布版本和可用时的正式版本分别构建配套产物，执行同一正确性、远程协议和观测验收集，比较公开行为。

**Acceptance Scenarios**:

1. **Given** 当前基线和明确版本/提交的 DuckDB 2.0 预发布版本，**When** 使用各自配套扩展及远程依赖执行相同查询，**Then** 数据类型、坐标、值、过滤边界、计数、缺测、取消和缓存权限语义一致，差异有明确兼容处理。
2. **Given** 普通查询及复杂条件在版本间具有不同优化路径，**When** 执行，**Then** 保留完整条件、列依赖、位置覆盖和观测完整性；无法安全缩小的条件正常回退。
3. **Given** 非配套版本产物或远程能力不兼容，**When** 加载或远程读取，**Then** 明确拒绝并指出需要的版本组合，不尝试继续处理数据。
4. **Given** 2.0 正式版尚未固定并验收，**When** 查看支持矩阵，**Then** 标注为目标或预发布已验证，不能标为正式支持；正式版本可用后必须完成单独验收才声明正式兼容。

### User Story 7 - 区分网格支持与实际收益证据 (Priority: P2)

作为验收者，我希望知道每个 domain 的来源、样本覆盖、选择是否缩小、是否回退以及网络与解码成本，从而判断支持声明和性能结论是否成立。

**Why this priority**: 新类型定义存在、绑定成功或结果行数减少，都不足以证明坐标正确和远程收益。

**Independent Test**: 从固定来源重生 registry，查看逐 domain 覆盖记录；未参与实现的验证者依说明复现四类新网格、局部远程读取和空间关系示例。

**Acceptance Scenarios**:

1. **Given** 同一固定上游来源及完整生成输入，**When** 重生 registry，**Then** 得到相同定义身份和内容，不依赖运行时抓取最新定义。
2. **Given** 每类新网格的全扫、区域、空、回退和失败查询，**When** 查看记录，**Then** 可分别解释网格/坐标准备、逻辑候选、值读取、实际网络响应、解码、工作内存、任务与终态。
3. **Given** 仅有元数据样本或缺少真实样本的 domain，**When** 查看支持清单，**Then** 证据范围明确可见，不继承同类其他 domain 的完整验收结论。
4. **Given** 完整交付说明与固定样本，**When** 独立复现，**Then** 无需自行换算网格索引即可完成区域查询，并能依据成本判断优化是否生效。

### Edge Cases

- 投影边界弯曲、区域四角在网格外但内部相交、接缝不连续、极点、投影奇点、投影原点、跨半球和接近可表示数值边界；无法证明安全时不能误报空区域。
- Lambert 的标准纬线重合与不同半球、stereographic 中心处的有限极限、旋转极点方向、半径与单位不同；同名投影不能掩盖不同参数或地球模型。
- 同一地理纬度/经度不再对应独立网格行/列；native x/y 或旋转纬经度不能直接作为地理纬经度。
- Gaussian N160/N320 行长变化、北南顺序、赤道附近无恰好零纬度行、极区无恰好极点、不同来源纬度规则；不因标准定义与生产者近似不同而静默替换坐标。
- Gaussian 区域子集的局部首点、每行截取长度及环绕片段；全域与局部点数碰巧相同不足以确认身份。区域覆盖证据缺失或冲突必须拒绝。
- 0–360 经度、重复接缝点、-180/180 规范化、跨经线并集；反向普通 BETWEEN 仍为空，不隐式环绕。
- 反向步长、非方形、单行/单列、展平顺序、空间轴位于其他轴之间，以及 shape 一致但轴、参数或区域来源不同的变量。
- 碎片选择、候选重叠、多个片段落入同一压缩块、单个区域落在巨大块中；保守多读不等于错误，但不能宣称未实测收益。
- 计数含值过滤、重复坐标、相同点有多时次、未声明非空间轴、缺测和无穷；沿用逻辑记录与缺测规则。
- 任务不足、跨批次、LIMIT 提前停止、规划/坐标准备期间取消；未完整扫描不能计作全量性能证据。
- 冷/热缓存、对象替换、强/弱版本、权限改变、无效范围及配套依赖不匹配；新网格不能绕开远程限制。
- 地理角度、投影长度单位、平面/球面距离和面积、点/单元边界、网格向量/地理方向含义不同；不隐式转换或伪造能力。

## Requirements *(mandatory)*

### Functional Requirements

#### 网格定义、布局与兼容

- **FR-001**: 系统 MUST 在既有规则网格基础上支持旋转经纬度、Lambert conformal conic、stereographic 与 reduced Gaussian N 四类新网格；Gaussian N 至少覆盖 N160、N320，以及有明确局部映射证据的 N 区域子集。支持范围以发布的定义及证据清单为准。
- **FR-002**: 每类新网格 MUST 可用完整显式定义和固定命名 domain 表达；二者互斥，不按路径或 shape 自动选择。定义包含类型、地球模型/坐标参考系、参数及单位、原点、方向和点序所需的全部信息。
- **FR-003**: 投影空间 MUST 支持两个明确原始空间轴或明确顺序的展平点轴，并保留其他轴；地理坐标可以同时依赖两个空间位置。不能把投影 x/y 当作纬度/经度。
- **FR-004**: Gaussian 定义 MUST 明确纬度行坐标及来源、每行点数/经度规则、行顺序、展平点序和总点数；区域子集还须明确局部位置到完整网格的关系。不同纬度生成规则具有不同定义身份，不从 N 编号猜测未给出的行表或来源约定。
- **FR-005**: 系统 MUST 在返回数据前校验全部变量的有序轴、空间长度、网格身份、区域映射及存在的相关坐标参考系证据；冲突声明不能覆盖源证据，包围盒匹配不能单独证明投影或点序正确。无效参数、溢出、未知类型、列名冲突和不兼容布局须明确拒绝。
- **FR-006**: 新网格 MUST 输出有限的 `latitude DOUBLE` 与 `longitude DOUBLE`，纬度位于 [-90,90]，经度统一为 [-180,180)，按公布的地理坐标来源解释；参考容差在验收前固定。既有规则 domain 的已公布例外按原契约保留，不扩散到新网格。
- **FR-007**: 新能力 MUST 保持原始位置与值、多变量及五类语义维度对应，不隐式转置、广播、去重或重采样；原规则网格声明与未配置空间信息的值扫描继续符合既有 schema 和行为。

#### 安全空间选择与组合查询

- **FR-008**: 系统 MUST 对有限常量的地理坐标等值、大小比较、BETWEEN 和安全合取生成覆盖全部匹配点的候选位置，支持单/双坐标及与语义轴条件的交集；完整查询条件必须精确执行。
- **FR-009**: 选择 MUST 按源点真实地理坐标解释区域，在投影曲线、局部覆盖、接缝、极区及数值误差存在时保持保守；仅变换矩形四角、角点越界或粗略包围盒不足以证明无交集。不能证明时扩大候选并说明原因。
- **FR-010**: 支持的两个有限经度区间的安全并集 MUST 能与共同纬度条件组合并缩小候选；每个源位置最多出现一次。任一分支无法安全分析时不得只读取其他分支；允许扩大到全域并记录原因。普通反向 BETWEEN 不改变语义。
- **FR-011**: 筛选边界 MUST 依据实际输出坐标精确比较，验证容差不得变成用户条件的隐式容差；不支持的函数、转换、条件、奇点或超过预算的碎片选择必须安全回退。
- **FR-012**: 空间选择 MUST 与值过滤、列裁剪、重复引用、表达式、计数、排序、聚合及并行扫描组合；保留全部依赖，无关值变量不得解码，串行与并行结果多重集合一致。
- **FR-013**: 无值依赖的坐标/计数查询，以及可由坐标证明的空选择，MUST 保持值索引、值数据读取和值块解码为零；允许必要元数据与坐标证据读取，但须分别计量。
- **FR-014**: 选择与扫描 MUST 保持有界工作内存和可取消行为，不预先保存全部网格点坐标、全部候选记录或全量任务清单；超出公布选择预算时扩大候选，不能截断结果。

#### 本地与远程按需读取

- **FR-015**: 新网格 MUST 在本地、HTTP(S) 和 S3 的同内容对象上具有相同 schema、坐标、源位置、值及缺测语义；经纬度选择传递到对象实际逻辑读取位置，包括非连续片段、其他轴及 Gaussian 局部位置。
- **FR-016**: 远程区域查询 MUST 按需读取；每类新网格在事先固定的可跳块样本上，冷态局部查询的值数据字节、值块解码和实际响应 body 总字节均须严格小于同列全扫，包含绑定与坐标准备等全部传输成本。不能以预先完整下载、输出点数或候选数代替收益。
- **FR-017**: 地理选择 MUST 保持官方 OM reader 的既有物理读取职责；不假设地理矩形、一组点或连续索引必然对应一个连续字节范围，允许压缩块边界所需的多读，最终只返回符合完整条件的记录。
- **FR-018**: 新网格 MUST 沿用远程范围校验、权限检查、对象身份、缓存失效及取消语义；不支持范围、配套能力不匹配或可检测对象改变须明确失败，不静默完整下载或成功返回跨版本结果。缓存不得改变选择和精确结果。
- **FR-019**: 性能证据 MUST 使用同对象版本、列依赖、环境及明确缓存状态并完整消费结果；服务端交叉核对实际响应 body，所有重试已收 body 均计入成本。失败、不完整统计和提前停止不能计为成功全量收益。

#### 空间计算的可解释输入

- **FR-020**: 系统 MUST 让用户通过明确请求取得网格描述和源位置身份，而不改变既有默认输出；描述至少含定义身份/版本、原生与输出地理坐标参考系或可验证地球模型、轴顺序/单位、布局、点序及局部映射。源位置关联本次对象身份及可用版本证据，区别同经纬度的不同点及不同非空间记录；无法验证的对象版本须明确标识。
- **FR-021**: 网格身份 MUST 由影响坐标和布局的定义决定，不能仅为 domain 名、shape 或经纬度；过滤、排序、并行和批次变化不改变源位置含义，显式定义与等价 domain 可证明身份等价。
- **FR-022**: 交付 MUST 包含每类新网格的点与固定区域关系示例，明确参考系及经度在前、纬度在后的水平坐标顺序，与全域点精确判断核对；若用区域包围盒预筛选，仍须完整空间关系判断。普通读取不要求空间计算功能。
- **FR-023**: 网格描述 MUST 明确点/单元、邻接、周期接缝、距离/面积单位及向量方向的已定义或未支持状态，为后续 `om_slice`、`om_reduce`、`om_interp`、`om_regrid` 保留可追溯输入。当前不生成未经证实的单元边界、面积权重、Gaussian 矩形邻接或向量旋转结果。

#### DuckDB 2.0 兼容目标

- **FR-024**: DuckDB 2.0 MUST 作为后续正式支持目标；本期规划与实施须固定至少一个可用的 2.0 预发布版本/提交，与既有 1.5.x 基线分别验证同一网格、地理筛选、本地/远程、维度、缺测和观测语义。不得假定旧版本产物跨版本可用。
- **FR-025**: 支持矩阵 MUST 分别记录引擎版本/提交、配套扩展及远程依赖身份、平台、执行范围和状态；未知、不匹配组合明确拒绝。优化方式或内部 I/O 差异不能改变完整过滤、权限/版本边界、取消和统计完整性。
- **FR-026**: 2.0 正式支持 MUST 以固定正式版本通过相同正确性及远程验收为条件；预发布通过只能声明该组合已验证。正式版尚不可用时保留明确待验收目标，不能记为通过或据此宣称兼容。

#### 来源、观测与交付

- **FR-027**: 每类新网格 MUST 至少有一个固定身份的真实 OM 样本完成独立坐标与官方解码值对照，覆盖边缘、内部、行边界/接缝及适用布局；N160、N320 和至少一个 N 区域子集各须有独立定义/位置对照。合成样本补齐极值、布局和故障，不代替每类真实样本。
- **FR-028**: Registry MUST 能从固定上游版本与完整生成输入重生相同定义；每条目记录来源、参数、布局、坐标规则版本及证据范围，区分定义收录、元数据核对、坐标/值核对及远程收益验收，不从同类或旧网格推定新条目通过。
- **FR-029**: 查询观测 MUST 区分网格类型/身份、坐标准备成本、选择模式、保守候选与扫描行数、回退原因、元数据/坐标/值索引/值数据读取、请求/实际响应 body、解码、缓存、任务/工作者、耗时、选择工作内存及终态/统计完整性；沿用查询隔离与脱敏。
- **FR-030**: 交付 MUST 提供固定样本、来源、独立参考、验收前容差、完整查询与实测证据，以及显式网格/domain、区域/接缝、零值读取、回退、空间关系和版本组合说明；支持范围变化须同步 README、接口说明、技术架构、查询契约和路线图，独立复现后方可标记相应范围验收完成。

### Key Entities *(include if feature involves data)*

- **网格定义**：网格族、投影/地球模型、参数与单位、坐标来源版本、原点/方向、行与点序；身份随有意义的参数和布局变化。
- **Domain 条目**：带固定来源、适用布局和证据范围的命名网格；名称不代表自动发现或统一验收等级。
- **Gaussian 行与区域映射**：每行纬度、点数、经度规则、全域行序和区域实际点序，连接对象局部位置与原生位置。
- **空间布局与源位置**：文件原始轴及位置到网格点、其他维度和变量值的关系；同坐标记录可有不同身份。
- **地理选择**：完整条件、安全覆盖的候选位置、联合维度条件、空选择与回退原因；候选不等于最终匹配。
- **网格描述与能力**：原生/地理参考系、单位、点语义和邻接/单元/面积/方向能力状态，供后续消费者解释输入。
- **对象与运行证据**：内容版本、访问上下文、来源、查询、缓存状态、参考、真实成本及终态；网格不改变对象身份规则。
- **版本支持组合**：引擎、配套扩展/远程依赖、平台及门禁状态，区分基线、2.0 预发布和正式目标。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 四类新网格各至少一个真实样本完成坐标和值核对；N160、N320 与一个 N 区域子集各有独立定义/位置对照。源位置、行数、缺测和解码值一致率为 100%，坐标全部满足验收前固定且不改变筛选语义的容差。
- **SC-002**: 验收覆盖单/双坐标、开闭边界、弯曲投影边界、角点越界但区域相交、极区、接缝并集、Gaussian 行边界、局部映射、反向/展平轴、额外维度及复杂条件回退；结果与完整扫描后过滤一致率为 100%，无遗漏或额外重复源位置。
- **SC-003**: 每类新网格在一个事先固定的可跳块样本上证明区域查询的值数据读取和解码量均严格下降；两个远程来源分别证明包含全部准备成本的冷态响应总字节严格下降，服务端交叉核对一致，与本地同内容结果完全一致。
- **SC-004**: 全部可证明空选择、无值依赖坐标和坐标计数的值索引、值数据及值块解码均为零；混合查询无关变量解码为零，必要坐标成本可辨认。
- **SC-005**: 代表每类新网格的多任务样本使用 1、2、4 个工作者上限完成核对，零遗漏、零额外重复；任务不足、跨批次、失败、取消和提前停止状态均正确。
- **SC-006**: 四类新网格各完成一个点与区域关系示例，位置身份可独立复原，与全域点精确关系基准一致率为 100%；未支持能力明确标识，无误标的单元、面积或方向结果。
- **SC-007**: 同类网格、相近窄区域结果规模及相同工作者/缓存配置、相同压缩块尺寸条件下，原始空间点数扩大至少 10 倍，选择/扫描工作缓冲峰值不超过对照的 2 倍；定义自身行表、必要输入坐标证据及共享缓存分别报告，不计入该工作缓冲比较。全部实测内存不超过事先公布的相应上界。
- **SC-008**: 相同固定来源重生两次网格清单，定义内容及身份一致率为 100%；每类均提供真实样本覆盖、来源版本与完整运行记录，元数据核对和完整验收无混淆声明。
- **SC-009**: 现有基线与至少一个固定预发布目标版本的公共查询验收全部通过，公开含义和失败边界一致；正式目标可用后通过同一套正式验收才能标记正式支持。各版本组合状态与范围可追溯。
- **SC-010**: 全部非法定义、证据冲突、范围异常、权限/版本改变和取消得到预期拒绝/终态；无成功返回的残缺或跨版本结果，每类失败后可再次成功查询。
- **SC-011**: 一名未参与实现的验证者仅凭交付说明完成四类新网格查询、一次远程区域成本比较及一次点与区域关系复现，从记录正确区分候选多读、精确结果、回退、缓存收益和正式/预发布支持。

## Assumptions

- 本 feature 对应 [产品路线图 Phase 6](../../docs/roadmap.md)，不是多文件扫描，也不是在一个值数组内混用多种网格。一次绑定针对单个 OM 对象和一个明确网格；同一 SQL 可分别查询不同网格对象，不隐式拼接或重网格。
- 依赖 [001](../001-local-om-scanner/spec.md)、[002](../002-spatial-pushdown/spec.md) 和 [003](../003-dimensions-remote-parallel/spec.md) 的行为及集成能力。003 远程 G3/G5/G6 和独立复现 G7 尚未完整验收；可先定义/实现本地网格，本期完整远程声明须补齐所依赖门禁，不从代码或本地通过推定远程完成。
- 最低投影范围是来源可核对的球面旋转经纬度、Lambert conformal conic 与 stereographic；Lambert 单/双标准纬线和极区应用须有明确定义。任意椭球投影、任意 WKT 自动识别、Mercator、Lambert azimuthal equal area、Gaussian O/F、非结构网格及任意二维坐标数组不是本期最低交付范围；扩展沿用定义与证据契约。
- Gaussian N 采用生产者已核对原生规则或明确独立纬度证据，不把生产者近似与标准 Gaussian 纬度混为同一版本，不静默“校正”原生位置。区域子集须有来源可核对的完整布局描述；缺证据时拒绝地理绑定。
- 经纬度表示原生点在公布地理坐标来源中的角度，不凭投影名将球面模型宣称为另一地理参考系。空间关系示例须统一参考系；未证实的基准转换、面积、距离、邻接和单元边界不隐式生成。
- 普通读取保留既有参数与默认列；新类型声明、描述及明确请求源位置的调用形式由 plan/契约确定。科学算子独立设计；本期不实现 `om_slice`、`om_reduce`、`om_interp`、`om_regrid`，不要求任意空间函数自动缩小源读取。
- OM 格式/值子集、NaN 到 NULL、非空间轴、对象稳定性、缓存授权和官方 reader 物理职责沿用现有契约。目录、glob、跨文件拼接、写入、自动 regrid 和新增压缩格式不在本期。
- 允许额外候选和必要压缩块多读；性能样本事先固定且确有可跳块布局，不对任意文件、极小区域或碎片查询承诺节省比例或延迟。
- 工作缓冲上界在 plan 中固定，区分持久定义/必要坐标输入、选择、批次、解码、输出及共享缓存；SC-007 比较选择/扫描工作缓冲，不通过将这些分配改名为定义规避计量。准备过程也须可取消。
- 继续明确验收 Linux AArch64，Linux x86_64 支持与验证延续暂缓。主要基线为 1.5.4，1.5.5 真实文件兼容记录须保留；plan 列明精确组合，不据局部样本宣称任意 1.5.x 均完整通过。
- 根据 [2.0 官方预发布说明](https://duckdb.org/2026/09/02/try-duckdb-20-alpha)，固定预发布兼容与正式版复验分别作为里程碑；规划时重新核对发布/提交，不猜测最终接口或正式发布时间。正式版验收目标不能因预发布通过而删除。
- [Constitution](../../.specify/memory/constitution.md) 仍是占位模板，不把示例当作原则；[路线图约束](../../.specify/memory/roadmap.md)和具体既有契约是依据。
- [planning-notes.md](planning-notes.md) 保存来源、范围解释及待规划取舍；候选设计不是实施承诺。规格质量通过只表示可以进入 `$speckit-plan`。
